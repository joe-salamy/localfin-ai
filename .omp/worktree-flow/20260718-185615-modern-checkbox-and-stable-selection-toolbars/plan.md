# Modern Checkbox and Stable Selection Toolbars

## Context

Modernize all 12 native checkbox renderings in the frontend, emphasizing Setup and Transaction History, without changing the custom selection indicators in `MultiSelect` or `TagPicker`. Replace browser-dependent checkbox painting with one refined monochrome control, and move the selected-count/delete controls for Transaction History plus the Accounts, Categories, and Subcategories tables into stable title rows so selecting records never pushes a table downward. Preserve the existing bulk-edit, bulk-delete, confirmation-modal, shortcut, fixed-column, and undo behavior.

## Approach

1. **Introduce one semantic native checkbox primitive and visual state contract.**
   - Add `src/components/ui/Checkbox.tsx`; no existing shared checkbox component exists. Follow `src/components/ui/Input.tsx`: `forwardRef`, native props, `cn`, `displayName`, semantic theme tokens, and explicit focus/disabled states. Use `src/components/ui/MultiSelect.tsx` only as the visual reference for a compact rounded square, primary checked fill, and Lucide mark; do not modify or reuse its faux option indicator because the chosen scope is native checkboxes only.
   - Export the exact API `interface CheckboxProps extends Omit<InputHTMLAttributes<HTMLInputElement>, "type"> { indeterminate?: boolean }` and `const Checkbox = forwardRef<HTMLInputElement, CheckboxProps>(...)`. Render a `relative inline-flex h-4 w-4 shrink-0` wrapper containing the real `<input>` and two absolutely centered, `pointer-events-none aria-hidden` Lucide marks. Force `type="checkbox"`; apply the merged `className` to the input; forward every other native input attribute and the caller ref. Keep the input focusable/clickable, style it with `appearance-none`, and use its `peer-checked`/`peer-indeterminate` state to reveal `Check` or `Minus` rather than replacing semantics with a button.
   - Apply the approved refined-monochrome states with existing tokens only: 16px (`h-4 w-4`) `rounded-sm` box; unchecked `border-border bg-background`; checked and mixed `border-primary bg-primary text-primary-foreground`; subtle `hover:border-foreground/60`; `transition-colors`; `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`; and `disabled:cursor-not-allowed disabled:opacity-50`. The check is visible only for checked/non-mixed state; the minus is visible only for mixed state. Do not add a Checkbox/Radix dependency, global `input[type="checkbox"]` CSS, hard-coded colors, animation, or checkbox variants.
   - Implement `indeterminate` by assigning `HTMLInputElement.indeterminate` whenever the prop or node changes while composing the forwarded ref; expose `aria-checked="mixed"` in that state. Preserve native Space-key behavior, form behavior, and wrapping-label click behavior. The chosen design combines [MDN’s native checkbox guidance](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/checkbox) for label hit areas and the imperative mixed state, [Radix’s checkbox state model](https://www.radix-ui.com/primitives/docs/components/checkbox) for checked/unchecked/indeterminate visuals and keyboard behavior, and the compact rounded-square treatment shown by [shadcn/ui’s Checkbox](https://ui.shadcn.com/docs/components/radix/checkbox), but implements those ideas with the repo’s existing native/Tailwind conventions and no new dependency.

2. **Replace every native checkbox callsite and add complete table selection states.** This step depends on step 1; migrate all callers in one clean cutover and leave no native checkbox markup or duplicated checkbox class strings behind.
   - In `src/components/features/TransactionTable.tsx`, replace the select-all and per-row inputs with `Checkbox`. Preserve `allSelected`, `toggleAll`, `toggleOne`, `selectedIds`, and `onSelectionChange`. Add exact names `aria-label="Select all transactions"` and `aria-label={`Select ${t.name}`}`. Disable select-all when `transactions.length === 0`. Derive `someSelected` as at least one currently rendered transaction ID in `selectedIds` while `allSelected` is false, then pass `indeterminate={someSelected}` to the header checkbox. Do not alter the fixed 48px selection column, `<colgroup>`, persisted resize behavior, table layout, or spreadsheet cell selection.
   - In `src/components/features/setup/AccountsSection.tsx`, `CategoriesSection.tsx`, and `SubcategoriesSection.tsx`, replace each header/row input with `Checkbox`. Preserve the existing handlers and labels (`Select all accounts/categories/subcategories`, `Select ${name}`), the empty-list disabled header, and omission of row selectors for system categories/subcategories. For each header, pass `indeterminate={selectedCount > 0 && !allSelected}`; `selectedIds` contains only selectable rows under the existing toggle paths, so no new selection state is needed.
   - In `src/pages/SettingsPage.tsx`, replace the four inputs for success-confirmation popups, amount gradient, shortcut hints, and disabling single-key shortcuts. Preserve each `checked`/`onChange` pair and the existing wrapping `<label>` so the visible text remains the accessible name and click target.
   - Do not modify `src/components/ui/MultiSelect.tsx` or `src/components/features/TagPicker.tsx`: they are button-based option indicators, not native/ARIA checkboxes, and the selected scope explicitly excludes them.

3. **Make Transaction History selection actions dimensionally stable.** This step is independent of the Setup toolbar relocation in step 4 after the checkbox primitive exists.
   - In `src/pages/TransactionHistoryPage.tsx`, replace the standalone `Transaction History` `<h1>` with one stable heading/action grid at the same top-of-page location. Always render a non-interactive `h-7` action slot; render the selected count and buttons inside that slot only when `selectedIds.size > 0`. At `sm` and wider, use `grid-cols-[1fr_auto]` with the heading left and slot right in one `min-h-7` row. Below `sm`, use two explicit `h-7` rows separated by a fixed gap (`min-h-16` total), with the action slot on row two. This keeps identical geometry at zero and nonzero selection without leaving hidden buttons in the accessibility tree.
   - Reuse the existing exact count text, `Bulk Edit`/destructive `Bulk Delete` buttons, `ShortcutHint`s, `setBulkEditOpen(true)`, and `setBulkDeleteOpen(true)` callbacks inside the stable slot.
   - Delete the old conditional `Action bar` sibling at the current pre-table location. Keep `selectedIds`, shortcut enablement, `handleBulkDelete`, undo registration, `BulkEditModal`, and `ConfirmDeleteModal` unchanged; the existing modal remains an overlay and is not the source of the shift.
   - At desktop width the heading and controls must read on one line as `Transaction History` on the left and `{n} selected`, `Bulk Edit`, `Bulk Delete` on the right. At narrow width the reserved second row may hold the actions, but selecting the first row must not change the table’s top coordinate.

4. **Attach stable selection captions to all three Setup tables.** This step is independent of step 3 and avoids lifting feature-owned selection state into `SetupPage`.
   - In each of `AccountsSection`, `CategoriesSection`, and `SubcategoriesSection`, remove the current conditional bordered selected-count/Delete Selected banner near the start of the section.
   - Add a semantic `<caption>` to the corresponding fixed-layout table. Put `pb-2` on the caption, then render an exactly `h-7` `flex items-center justify-between gap-3` toolbar with the table title (`Accounts`, `Categories`, or `Subcategories`) on the left and an always-present, non-interactive `h-7` action slot on the right. Render the existing count and destructive `Delete Selected` button inside that slot only when `selectedCount > 0`; an empty slot preserves height without hidden interactive controls. Keep the table’s current `minWidth` so this toolbar stays one line and scrolls with the table at narrow viewport widths rather than wrapping.
   - Reuse each section’s exact pluralized selected-count copy, `Trash2` icon, `ShortcutHint`, modal-opening callback, and existing `ConfirmDeleteModal` message/handler. Do not place action buttons in `CollapsibleSection`’s disclosure button: nested interactive controls would be invalid, and the child sections currently own selection state.
   - For Accounts, place the caption on the account table after the unchanged Linked Providers card. The caption—not the providers card or outer collapsible title—owns the selection controls. Selecting the first row in any Setup table must leave that table’s top coordinate unchanged.

5. **Defend the new semantic and interaction contracts without testing CSS source text.**
   - Add `src/components/ui/Checkbox.test.tsx` using Testing Library/user-event. Verify a labeled checkbox toggles by label click and Space; checked and disabled semantics remain native; a forwarded ref receives the input; and rerendering `indeterminate` sets/clears both the DOM `indeterminate` property and mixed accessible state. Leave mark appearance to the browser check rather than asserting SVG/class implementation details.
   - Update `src/components/features/TransactionTable.test.tsx` to query `Select all transactions` and `Select Corner Market` instead of positional `getAllByRole`. Preserve the controlled selection callback assertions. Add `secondTransaction` by cloning the existing fixture with `id: "transaction-two"`, `name: "Fuel Stop"`, and `date: "2026-07-02"`; rerender both rows with only `transaction-one` selected and assert the header is mixed, then click select-all and assert `onSelectionChange` receives both IDs. Add an empty-table assertion that `Select all transactions` is disabled.
   - Do not add page/section tests for geometry: jsdom cannot measure layout, `TransactionHistoryPage` requires broad hook mocking, and `SetupPage.test.tsx` deliberately mocks all three checkbox-bearing sections. Preserve `SetupPage.test.tsx` as the route/disclosure regression; prove toolbar placement, modal wiring, and invariant table coordinates in the real browser scenarios below.

## Critical files & anchors

- `src/components/ui/Input.tsx` — copy its `forwardRef`, `cn`, semantic focus-ring, and disabled conventions for the new primitive.
- `src/components/ui/MultiSelect.tsx` — visual-only reference for the compact monochrome square and Lucide check; explicitly do not change its button semantics.
- `src/components/features/setup/SetupSection.tsx` — confirms the section title is already an interactive disclosure; keep bulk actions out of that button and use table captions instead.
- `src/features/transaction-history/transactionHistoryColumns.ts` — preserves the 48px Transaction History selection column during the control swap.
- `src/components/features/setup/setupShared.ts` — preserves the three Setup tables’ 48px selection columns and fixed-layout geometry.

## Verification

- From the repository root with the existing dependencies installed, run the focused semantic/interaction tests:
  - `npm run test:frontend -- src/components/ui/Checkbox.test.tsx src/components/features/TransactionTable.test.tsx src/pages/SetupPage.test.tsx`
  - Expected: native label/keyboard/disabled/ref/mixed behavior passes; transaction row/select-all callbacks pass; existing Setup route/disclosure behavior remains green.
- Run `npm run typecheck` from the repository root. Expected: the new `CheckboxProps`, composed ref, and all 12 migrated callsites compile without errors.
- Start the real app from the repository root with `npm run dev`; no provider credentials are required. Use the UI to create at least one ordinary account, one ordinary category, one ordinary subcategory, and two transactions dated within the default last-30-days filter. Fresh seed categories/subcategories are system records and intentionally have no row checkbox.
- At `http://localhost:5173/setup`, expand Accounts, Categories, and Subcategories. For each table: record `table.getBoundingClientRect().top`; select one row; verify the header shows a minus, the row shows a check, the right caption shows the correct count/Delete Selected action, and the recorded top is unchanged; select all and verify the header changes to a check; clear all and verify the action group disappears without movement. Confirm system rows remain unselectable, empty selectable tables disable select-all, keyboard Tab/Space works, and focus rings/checked/disabled states are legible in the dark theme. Open and cancel each Delete Selected confirmation to prove existing modal behavior remains connected.
- At `http://localhost:5173/transactions/history`, at both a desktop viewport and a narrow mobile viewport: record the transaction table’s `getBoundingClientRect().top`; select one row and verify the named row checkbox, mixed select-all minus, count, Bulk Edit, and Bulk Delete controls; verify the table top is unchanged; use select-all and verify all rows plus the header are checked; open and cancel Bulk Delete and confirm its existing count-sensitive dialog. Repeat keyboard Tab/Space and visible-focus checks.
- At `http://localhost:5173/settings`, toggle all four preferences by clicking both each checkbox and its wrapping label; verify the refined monochrome checked/unchecked/focus states and unchanged preference behavior.

## Assumptions & contingencies

- “All checkboxes” means the 12 real native checkbox callsites found under `src/`; `MultiSelect` and `TagPicker` are intentionally unchanged because their selection affordances are button content, not checkbox controls.
- The selected action groups remain hidden at zero selection, but their title/caption containers reserve the selected-state height. If an existing Tailwind utility cannot express the planned mixed-state icon selector, render the icon from the controlled `checked`/`indeterminate` props while keeping the native input and exact public API; do not fall back to browser-default painting or add a dependency.
- Setup bulk controls use table captions rather than the outer collapsible headings because selection state is feature-owned and the headings are disclosure buttons. If browser table-caption layout does not honor the fixed `h-7` inside the existing overflow container, place the same always-rendered `h-7` title/action toolbar immediately before the table inside that container; keep the exact titles, right alignment, and invariant top-coordinate behavior.
