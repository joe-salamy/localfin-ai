# Comprehensive Tech Debt Refactor

## Context
LocalFin AI needs a comprehensive, behavior-preserving cleanup rather than a rewrite. The end state is a reproducible and vulnerability-free toolchain, complete static analysis, correct centralized HTTP error semantics, versioned transactional database migrations, rendered React interaction coverage, smaller feature-focused UI and backend modules, and one neutral source of shared domain/API contracts. Implementation is ordered so characterization and verification precede structural movement.

### 3. Centralize HTTP errors without changing successful response contracts
1. Add `server/errors.ts` with the exact transport-neutral operational vocabulary: `type OperationalStatus = 400 | 403 | 404 | 409 | 413 | 502`; `class OperationalError extends Error { readonly isOperational = true; constructor(message: string, readonly statusCode: OperationalStatus, options?: ErrorOptions) }`; subclasses `BadRequestError`, `ForbiddenError`, `NotFoundError`, `ConflictError`, `PayloadTooLargeError`, and `UpstreamServiceError`; and `publicErrorMessage(error: unknown): string`, which returns an operational error’s message and otherwise the literal `"Internal server error"`. Preserve original provider/client failures as `cause`; add no aliases and infer no status from message text.
2. Change `parseRequest` in `server/routes/validation.ts` from `(schema, value, res): T | null` to `parseRequest<T>(schema: z.ZodType<T>, value: unknown): T`. Throw `BadRequestError` with the existing ordered `"; "`-joined Zod issue messages. Update all callsites in `account-linking.ts`, `accounts.ts`, `ai.ts`, `categories.ts`, `dashboard.ts`, `goals.ts`, `parser.ts`, `tags.ts`, and `transactions.ts`; remove the Response argument and impossible nullable-return branches while retaining all current schemas, collection limits, real-date checks, and refinement messages.
3. Convert route-facing service failures at their source without changing service signatures or established message literals: missing accounts/categories/subcategories/tags/goals/transactions/conversations/provider connections become `NotFoundError`; duplicates, restore-name collisions, protected system entities, dependent-category deletion, duplicate provider transactions, duplicate goals, and inactive provider connections become `ConflictError`; malformed business input and `TransactionSearchSyntaxError` become/extend `BadRequestError`. Keep AI tool-loop validation as action failures because `chat-runner` consumes it. Missing environment/configuration, decryption failures, impossible post-insert states, SQLite errors, and programming errors remain ordinary errors and therefore safe generic 500s.
4. Translate non-2xx, malformed, or empty Plaid, Akoya, and OpenRouter responses at their client boundaries to `UpstreamServiceError` with stable literals `"Plaid request failed"`, `"Akoya request failed"`, and `"OpenRouter request failed"` and the detailed/redacted original as `cause`. Do not expose provider bodies, environment keys, or credential errors.
5. Export `errorHandler: ErrorRequestHandler` from `server/app.ts`. Change CORS rejection to `ForbiddenError("Origin not allowed by CORS")`. Add a terminal JSON 404 `{ success: false, error: "Route not found" }` before `errorHandler`.
6. Remove ordinary route `try/catch` blocks from all nine route modules and rely on Express 5.2 rejected-promise propagation; preserve every successful status/envelope, including 200 deletes, 201 creates, conditional account reconcile 200/201, and special-route ordering before `/:id`. Retain only two protocol-specific catches: the Akoya callback always redirects and uses `publicErrorMessage`; the SSE chat route validates before headers, delegates pre-header errors, and after headers emits one `event: error` containing a JSON payload with `publicErrorMessage` before ending. No arbitrary exception message may enter a redirect URL or SSE event.
7. Add `server/app-routes.test.ts` using the temporary database, ephemeral server, Fetch, and API-envelope pattern in `server/account-linking-routes.test.ts`. Add `server/provider-clients.test.ts` and `server/openrouter.test.ts` with mocked Fetch responses to prove non-2xx/malformed provider/OpenRouter responses translate to the stable 502 literals with detailed originals only in `cause`. Update direct service tests to assert subclass/status and preserve existing message assertions.
