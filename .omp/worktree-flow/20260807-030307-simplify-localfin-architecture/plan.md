# Simplify LocalFin Architecture

## Context

Simplify all eight audited complexity areas in one staged implementation: remove obsolete OpenRouter streaming code, unify chat contracts and tool validation, migrate categorization to LangChain structured output, consolidate duplicated spreadsheet mechanics, reduce chat stream state, share agent harness primitives, and centralize small repeated validators. Preserve finance rules, persistence, primary chat/API behavior, and current table interactions; deliberately remove streamed reasoning and raw model-response diagnostics from the SSE contract and chat UI.

## Approach

### 1. Establish shared schemas and transport contracts

- Export Zod schemas alongside the canonical domain types: `accountTypeSchema`, `categoryTypeSchema`, `tagTypeSchema`, `goalPeriodSchema`, and schemas for `SuspectFindingStatus`, `SuspectSeverity`, and `SuspectReasonCode`; reuse `transactionKindSchema`. Replace every private copy in account/category/tag/goal/transaction/AI routes, nested shared dashboard/provider/transaction/parsing contracts, and assistant tool definitions. Keep provider-specific Plaid/Akoya institution schemas narrow.
- Add pure `isIsoDate` and canonical `hexColorSchema` to `shared/validation.ts`; use them from route Zod schemas, tool definitions, and `server/services/transaction-search.ts`, preserving each boundary's existing error text/nullability. In `server/routes/validation.ts`, centralize only the exact duplicate `optionalQueryStringArray` coercer. Keep the one-use `optionalQueryBoolean` and numeric pagination schemas local to transactions; derive the dashboard tag-filter schema by extending its date-range schema rather than duplicating the date refinement.
- Make `shared/contracts/parsing-ai.ts` the single transport contract. Server chat code and `server/services/agent-conversations.ts` must import `ChatRequest`, `ChatResult`, `PlannedChatAction`, `ChatActionResult`, `AgentConversation`, and `AgentMessage` instead of redeclaring equivalent interfaces. Keep DB row/input interfaces plus `AssistantContext` and `ChatStreamEmitter` server-local. Preserve the conversation loader's tolerant legacy `actions_json` parse while typing successful arrays as the shared action shape; do not make old sparse rows unreadable.

### 2. Make tool schemas the only scalar-validation source

- Add `server/services/ai-chat/tool-definitions.ts` containing each tool's name, description, strict Zod schema, the `FinanceToolName` union, the inferred discriminated `FinanceAction` union, and `parseFinanceAction(action: PlannedChatAction): FinanceAction`. Define trimmed strings and finite numbers once in this module and reuse shared enum/date/color schemas; do not make finance services depend on route validators.
- `parseFinanceAction` must reject an unknown tool with the existing literal `Unsupported action "<type>"`; for a known tool with invalid input, the exported direct seam returns `Invalid <type> input: <semicolon-joined Zod issue messages>` as `ChatActionResult.status = "error"`. Native LangChain calls reject invalid schema input before runtime action/events are appended.
- Keep every existing schema-visible tool name and field. Remove only hidden executor aliases that native tool calls cannot declare: camel-case tag aliases, singular create/update tag IDs where schemas expose arrays, snake-case search dates, `update_tag`'s hidden target/type aliases, and bulk-update fields outside `updates`; make `bulk_update_transactions.updates` required. Preserve declared singular/plural search tag filters, canonical `subcategory_name` fields, and all current nullability. Update descriptions, prompts, mocks, and direct executor tests to the canonical keys.
- Change the exported direct seam `executeAction(action: PlannedChatAction): ChatActionResult` to parse once with `parseFinanceAction`, then delegate to typed `executeFinanceAction(action: FinanceAction)`. Make `defineFinanceTool` generic over its Zod schema so LangChain's already-parsed `z.output<Schema>` invokes `executeFinanceAction` directly without a cast or second parse. Delete scalar/enum/date coercion from `action-executor.ts` and `input-validators.ts`; retain typed update-presence/date-range checks and every DB-dependent/domain invariant.
- Replace record-shaped entity helpers with `EntityReference = { id?: string; name?: string }`, `resolveEntityReference(items, reference)`, and `resolveRequestedEntityReference(actionType, label, items, reference)`. Callers pass canonical pairs such as `{ id: input.account_id, name: input.account_name }` or `{ id: input.id, name: input.current_name }`; keep tag type filtering and goal-by-subcategory resolution as typed domain-specific wrappers.
- Retain finance behavior in the typed executor/services: required targets and nonempty updates, search defaults/hard caps and query DSL, date ordering against current goals, account-aware amount normalization, transfer/adjustment subcategory clearing, active entity checks, explicit-only tag creation plus add/remove/replace semantics, bulk conflict detection, action ordering, and partial-failure results.
- Build `createAssistantTools` by mapping the definitions through the existing `defineFinanceTool` event adapter. Keep both `modelKwargs.parallel_tool_calls = false` and the serial queue: the provider setting prevents normal parallel calls, while the queue protects ordered finance mutations if a provider or test emits sibling tool calls.

### 3. Migrate categorization to LangChain structured output

- Add `getOpenRouterApiKey()` beside `ENV_KEYS`/`OPENROUTER_CONFIG`, preserving the exact missing/placeholder check/message; use it from the raw client until step 5 deletes that client. Replace `server/services/ai-chat/model.ts` with shared `server/ai/model.ts`: `createOpenRouterChatModel(model: AIModel, options?: { disableParallelToolCalls?: boolean }): ChatOpenRouter`. It owns key lookup and temperature `0`; assistant chat passes `{ disableParallelToolCalls: true }`, categorization uses the default, and the live-eval preflight keeps its script-specific guard.
- In `server/services/ai.ts`, define a `z.strictObject` result schema with `results: z.array(z.strictObject({ kind: z.enum(["income", "expense", "transfer"]), subcategory_id: z.string().nullable() })).max(AI_CONFIG.batchSize)` and invoke `createOpenRouterChatModel(AI_MODELS.transactionCategorization).withStructuredOutput(schema, { method: "functionCalling", includeRaw: false, name: "categorize_transactions" })`. Describe fields in the schema; require one result in input order and list valid subcategory IDs with category/type labels in the prompt. No numeric kind, subcategory, or transaction indexes remain; ignore any accepted output items beyond the corresponding input batch length.
- Continue exact-name lookup, transfer detection, account-type kind inference, configured batch size, and per-batch fallback behavior. Create prompt batches before constructing the model; wrap `createOpenRouterChatModel(...).withStructuredOutput(...)` so a synchronous missing/placeholder-key failure emits one safe error log per batch and returns all prefilled `source: "none"` results. Otherwise replace `processWithConcurrency` with `structuredCategorizer.batch(inputs, undefined, { maxConcurrency: AI_CONFIG.maxConcurrentLLMRequests, returnExceptions: true })`; the Runnable returns positional outputs/errors, but no matching tool call may yield `undefined`, so accept only outputs passing `categorizationSchema.safeParse`. Resolve accepted batches by input position: use a subcategory only when its ID exists and category type matches the kind; transfers clear it; missing items/invalid IDs use the inferred/returned kind's `Unassigned` row with `source: "ai"`. If that row is absent or an output is an `Error`/absent/invalid, leave only the affected prefilled results at `source: "none"`; network/provider failures use this same per-batch path.
- Delete numeric-choice/index-repair code (`AIResultItem`, `AvailableSubcategoryChoice.number`, `normalizeAIResultIndex`, numeric choice formatters/resolvers, `resolveAIResults`, and the custom worker pool) after all callers use ordered structured results. Append one metadata-only `transaction.categorize` success/error event per batch with model, request ID, timing, batch size/number/count, and unknown indexes; log only a fixed failure label/error class, never prompts, parsed tool arguments/output, raw provider payloads, provider error messages, or secrets. Replace the current `console.error(..., error)` with the same safe batch/error-class summary.

### 4. Trim diagnostic streaming and replace chat bookkeeping

- Add `src/components/features/chatStreamState.ts` with the pure `ChatUiState = { messages: ChatMessage[]; stream: StreamState | null }` reducer. Its action union includes all retained `ChatStreamEvent` variants plus local `request_started`, `user_message`, `messages_loaded`, `conversation_reset`, and `{ type: "transport_error"; id; message }` actions. It owns existing status literals, immutable action-index upserts, assistant final/error insertion, and in-flight clearing; a server `error` uses the current request ID as its message ID, while the component supplies an ID for pre-start transport errors, so the reducer stays deterministic.
- In one end-to-end contract change, remove `reasoning_delta`, `reasoning_details`, and `response_delta` from `ChatStreamEvent`, `chatStreamEventSchema`, `runAssistantChat`, `useAI`, and `ChatSidePanel`. The retained wire event set is exactly `started`, `thinking`, `actions_planned`, `action_started`, `action_finished`, `final`, and `error`.
- Simplify `runAssistantChat` to consume LangGraph `streamMode: "updates"` only and iterate the installed API's node-keyed update objects directly instead of tagged `[mode, payload]` tuples. Keep collecting model-update messages for planned actions and the final assistant text; remove `AIMessageChunk`, reasoning extraction, token forwarding, and raw response accumulation. Preserve request/action logging, conversation persistence, recursion limits, final error suffixes, and the non-stream and SSE routes. This intentionally removes token events accepted by the user; the primary assistant text still arrives in `final`.
- In `ChatSidePanel.tsx`, use `useReducer` for transcript and lifecycle state, keep only toast/cache side effects in `handleStreamEvent`, and remove scattered message setters, `streamStateRef`, reasoning arrays, response drafts, `reasoningDetailText`, the log-file hint, and both diagnostic `<details>` renderers. Final assistant messages continue to render text and completed action details; non-abort transport/SSE errors append the current error message and clear in-flight state, while an aborted unmount still adds nothing. Preserve finance-query invalidation on successful final actions and conversation cache invalidation in `useAI.ts`.

### 5. Remove the obsolete raw OpenRouter client

- With categorization and chat diagnostics migrated, reduce `server/ai/openrouter.ts` to conversation-log concerns and rename it to `server/ai/conversation-log.ts`. Delete `callOpenRouter`, `streamOpenRouter`, the manual JSON/SSE parsers, raw response/chunk/reasoning types, raw-client redaction/error translation, and now-unused OpenRouter URL/default-operation configuration. Update all logging imports and replace `server/openrouter.test.ts` with focused shared-model and categorization tests rather than retesting a deleted HTTP client.

### 6. Complete the existing spreadsheet-selection abstraction

- Strengthen the existing `useSpreadsheetSelection` rather than introducing a table library or generic renderer. It owns index-based range state, per-cell Ctrl/Cmd removal, Shift/additive document-level pointer drag, temporary `body.style.userSelect`, focus suppression, bounded arrow movement, select-all/clear methods, cell-state calculation, and the 1200 ms copied-highlight timer. Expose read-only state plus method-based mutation; remove raw setters, drag state, and internal refs from its public controller.
- Add only two pure helpers to `selection.ts`: `isSpreadsheetArrowKey(key)` and `buildClipboardMatrix(ranges, readCell)`. The matrix helper returns `null` for no selection, emits blank holes inside discontiguous bounding ranges, and never knows transaction rows or fields. Keep clipboard event gating, value parsing/application, persistence, toasts, and undo/redo table-local because History groups async transaction updates while Add Transactions mutates/grows draft rows.
- Migrate `TransactionTable.tsx` and `MultiTransactionTable.tsx` to the corrected controller and matrix helper. Delete duplicate copied timers, drag effects/base-range refs, selection toggles, arrow predicates/movement, and nested copy-matrix traversal. Preserve History's seven logical fields, row checkbox/edit state, grouped updates, and native-control guards; preserve Add Transactions' eight logical fields, row growth, amount normalization, snapshot undo, Enter/F2 editing, and explicitly prevent grid Ctrl/Cmd+A from hijacking native input/textarea selection. Leave `useResizableColumns` and both renderers unchanged.

### 7. Share deterministic agent harness primitives

- Add `server/testing/agent-eval.ts` containing transport-neutral seed/snapshot/assertion primitives: seed and snapshot types, injected service interfaces, `seedAgentScenario`, deterministically ordered `readAgentSnapshot`, normalized text/amount predicates, entity/transaction selectors, soft-deleted-row counts, action-count/success/search-before-update checks, and ordered-lifecycle plus allowed-event-set checks over shared `ChatStreamEvent`. It must not import `node:test`, mock `fetch`, call LangChain/OpenRouter, mutate environment, or write reports.
- Update `scripts/agent-live-eval.ts` to import those primitives and shared `ChatResult`, `ChatActionResult`, and `ChatStreamEvent`, while retaining scenario prompts, real-model loading/execution, environment preflight, and report presentation locally. Update `server/agent-system.test.ts` to reuse snapshot/deletion/lifecycle primitives while retaining `createFixture`, OpenRouter mocks, log reading, and bespoke integration assertions. Delete only duplicated helper declarations after both consumers migrate; do not build a generic test framework.

### 8. Consolidate the remaining narrow helpers

- Add `assertEntityNameIsUnique(name: string, exclude?: { table: "accounts" | "categories" | "subcategories"; id: string }): void` in `server/services/entity-name-uniqueness.ts`. Use a static query per table, preserve exact case-sensitive active-row matching plus account/category/subcategory message precedence, and call it from all three entities' create/rename paths. Delete both private `checkNameUniqueness` implementations; keep entity-specific restore checks and tag name/type uniqueness separate.
- Finish replacing all domain enum/schema and query-coercion duplicates identified in step 1. Do not create generic CRUD repositories, merge the two table renderers, or generalize tag uniqueness: those abstractions would erase real domain differences rather than simplify them.

## Critical files & anchors

- `server/services/ai-chat/action-executor.ts` — `executeAction`; preserve this as the typed finance-invariant boundary rather than moving domain behavior into LangChain callbacks.
- `server/services/ai.ts` — `categorizeTransactions`, batching, prompt construction, and result recovery; this is the remaining hand-rolled model protocol.
- `src/features/spreadsheet-selection/useSpreadsheetSelection.ts` — existing controller methods and incomplete pointer handlers; extend this seam instead of adding a second grid abstraction.
- `src/components/features/ChatSidePanel.tsx` — `handleStreamEvent` and `StreamState`; source behavior/status literals for the reducer before removing diagnostics.
- `scripts/agent-live-eval.ts` — seed/snapshot blocks and scenario boundary; move only deterministic fixture primitives, not live reporting or model execution.

## Assumptions & contingencies

- Deliver all eight areas in one implementation with the ordered sections above as independently testable checkpoints; step 4 is one atomic server/shared/client contract checkpoint.
- Remove diagnostic reasoning/raw-response streaming and presentation. Retain summary JSONL logging, but replace raw OpenRouter request/response payloads with fixed safe failure classification, timing, model, request ID, and batch metadata only.
- Use only installed dependencies. `@langchain/openrouter` 0.4.6 supports Zod v4 `withStructuredOutput(schema, { method: "functionCalling", includeRaw: false })`, and `@langchain/core` 1.2.5 supports `batch(inputs, options, { maxConcurrency, returnExceptions: true })` with positional outputs/errors; do not add concurrency, SSE, or table packages.
- Keep both HTTP chat routes, the SQLite conversation format and tolerant legacy action loading, finance mutations, schema-visible tool names/fields, primary assistant text/actions, and table UX. Hidden executor aliases receive a clean cutover; no deprecated shims remain.
- The configured assistant model already uses tool calling. If a credentialed categorization smoke proves that OpenRouter rejects the forced structured tool, switch only the structured runnable to `{ method: "jsonMode", includeRaw: false }`, which matches the current provider's JSON-object capability while retaining Zod parsing; do not restore the custom HTTP client, raw parser, or numeric repair protocol.
- If no archive backup is available for browser verification, use only `data/testing/simplification-smoke.db`; never exercise mutating table smoke checks against `data/budget.db`.
